Help

A short description of how a sequence is produced. The workbook supplies the locations, cables, and programme dates. The constraints you save are the rules.

How the app works

  1. 1Create a project
  2. 2Upload a workbook on Data
  3. 3Create a scenario and choose its dataset version
  4. 4Set FOU per trip, WTG per trip, and the solver time
  5. 5Add constraints, choose hard or soft, and leave active the rules to use
  6. 6Generate a sequence
  7. 7Review validation, the visual, the progress graph, and the Excel export

One scenario keeps the dataset version you selected. Uploading a newer workbook does not change that scenario until you edit its dataset. An inactive constraint stays on the scenario and is left out of the solve. Cancel stops a run that has already started and stores no sequence.

The solver

Sequencer uses Google OR-Tools CP-SAT. Each package has one installation order. The trip number and the position on the vessel follow from that order and the trip size. When IAC or WTG locations are included, FOU, IAC, and WTG are solved together in one model. The packages do not wait for each other unless a Package buffer constraint says so.

A hard constraint is a requirement. The solver has to meet it. A hard constraint is not turned into a soft one, and it is not dropped to produce a sequence. After the solver stops, the same hard rules are checked again on the stored order. If that check fails, the run is invalid and is not an approved sequence.

A soft constraint is a preference. Severity from 1 to 100 sets how strongly it pulls against the other soft preferences. A soft break keeps the run valid and records a penalty.

If no feasible order exists, the search ends without a proven result, or the solver reports an error, no sequence is stored. The time limit is 1 to 600 seconds.
